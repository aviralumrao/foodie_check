What is Pack Sure?

Pack Sure is an AI-powered compliance verification system for food packaging that ensures products meet India's Legal Metrology Act requirements. Built for Smart India Hackathon (SIH), it uses OCR and intelligent rule validation to scan packaging images and generate instant compliance reports.

Problem Statement Manual verification of food packaging compliance is time-consuming and error-prone. Pack Sure automates this process using computer vision and rule-based validation.

Key Features

📸 Dual Image Scanning

Upload front and back packaging images for comprehensive text extraction using PaddleOCR.

🔍 Smart Field Mapping

Intelligent pattern matching to extract MRP, manufacturing date, FSSAI license, net quantity, and more.

✅ Legal Compliance Check

Validates against 8 Legal Metrology Act rules with passed/needs review/failed status.

📊 Instant Reports

Visual compliance dashboard with detailed evidence and regulatory references.

💾 History Tracking

PostgreSQL database stores all scans with full OCR data and compliance results.

🌐 Modern Web Interface

Next.js 16 frontend with React 19, TailwindCSS, and responsive design.

Core Processing Pipeline

1️⃣ OCR Engine

Technology: PaddleOCR

Extracts text blocks with confidence scores and bounding boxes from images

{ "text": "MRP: Rs. 150", "confidence": 0.95, "bbox": [[x1,y1], [x2,y2], ...] }

2️⃣ Field Mapper

Location: mapping/field_mapper.py

Uses regex patterns to identify and extract required fields:

  • Pattern matching per text block
  • Fuzzy matching across combined text
  • Conflict detection between front/back
  • Address scoring with keyword matching

3️⃣ Rule Engine

Location: rules/engine.py

Validates each field against Legal Metrology Act requirements:

  • check_presence: Basic existence check
  • check_presence_with_hedge: Allows "see cap" phrases
  • check_presence_multi: Multiple address validation

Database Layer

🗄️ PostgreSQL Database

Stores scan results with full OCR data and compliance evaluations

Legal Metrology Act Rules

Pack Sure validates packaging against 8 mandatory declarations from India's Legal Metrology Act, 2009.

Rule ID Legal Clause Field Description Check Type
LM6_1_b Rule 6(1)(b) common_name Common or generic name must be declared presence
LM6_1_c Rule 6(1)(c) net_quantity Net quantity must be declared presence
LM6_1_d Rule 6(1)(d) mrp MRP inclusive of taxes must be declared presence_with_hedge
LM6_1_e Rule 6(1)(e) mfg_date Month and year of manufacture/packing must be declared presence_with_hedge
LM6_1_a Rule 6(1)(a) manufacturer_address Name and address of manufacturer/packer must be declared presence_multi
LM6_1_f Rule 6(1)(f) best_before Best before / expiry date must be declared presence_with_hedge
LM6_1_g Rule 6(1)(g) consumer_care Consumer care details must be declared presence
FSSAI FSS Act 2006 fssai_license FSSAI license number must be displayed presence

Check Types Explained

presence

Logic: Field must exist with valid data

Returns:

  • ✅ Passed: Field found
  • ⚠️ Needs Review: Conflict between front/back
  • ❌ Failed: Field not found

presence_with_hedge

Logic: Field must exist OR hedge phrase detected

Hedge phrases: "see cap", "see bottom", "printed on lid", etc.

Returns:

  • ✅ Passed: Field found
  • ⚠️ Needs Review: Hedge phrase detected
  • ❌ Failed: Neither field nor hedge phrase

presence_multi

Logic: Multiple address blocks detected (manufacturer address)

Returns:

  • ✅ Passed: One clear address found
  • ⚠️ Needs Review: Multiple addresses found
  • ❌ Failed: No address found

Pattern Matching Examples

// Net Quantity Pattern (?:Net\s*(?:Wt|Weight|Qty|Quantity)\.?\s*[:\-\.]?\s*(\d+[\.,]?\d*)\s*(?:g|kg|ml|ltr)) // MRP Pattern (?:M\.?\s*R\.?\s*P\.?|Maximum\s*Retail\s*Price)\s*[:\-\.]?\s*[₹Rs\.]*\s*(\d+[\.,]?\d*) // FSSAI License Pattern (?:FSSAI\s*(?:Lic|License)?\.?\s*(?:No\.?)?)\s*[:\-\.]?\s*(\d[\d\s]{10,})

PostgreSQL Database Schema

Table 1: scans

Primary table storing scan results and compliance evaluations

Column Type Constraints Description
id UUID PRIMARY KEY Unique scan identifier
user_id VARCHAR(255) NOT NULL, INDEX User who performed the scan
front_image_url VARCHAR(512) NOT NULL URL/path to front packaging image
back_image_url VARCHAR(512) NOT NULL URL/path to back packaging image
raw_ocr JSONB NULL Raw OCR text blocks from both images
extracted_fields JSONB NULL Mapped fields (MRP, dates, addresses, etc.)
rules_result JSONB NULL Array of 8 rule evaluation results
passed INTEGER DEFAULT 0 Count of passed rules
needs_review INTEGER DEFAULT 0 Count of rules needing manual review
failed INTEGER DEFAULT 0 Count of failed rules
overall_status VARCHAR(20) NOT NULL 'compliant' or 'non_compliant'
created_at TIMESTAMP DEFAULT NOW(), INDEX Scan creation timestamp
updated_at TIMESTAMP DEFAULT NOW() Last update timestamp

Table 2: compliance_rules

Reference table storing Legal Metrology Act rules

Column Type Constraints Description
id VARCHAR(50) PRIMARY KEY Rule ID (e.g., 'LM6_1_b', 'FSSAI')
field_name VARCHAR(100) NOT NULL Field being validated
clause VARCHAR(100) NOT NULL Legal reference (e.g., 'Rule 6(1)(b)')
check_type VARCHAR(50) NOT NULL Validation type
description TEXT NOT NULL Human-readable rule description
is_active BOOLEAN DEFAULT TRUE Whether rule is currently enforced

Table 3: users (Optional)

User account information if not using external auth

Column Type Constraints Description
id UUID PRIMARY KEY Unique user identifier
email VARCHAR(255) UNIQUE, NOT NULL User email
name VARCHAR(255) NULL User display name
created_at TIMESTAMP DEFAULT NOW() Account creation date
Important Notes for Backend Developer:
  • Use JSONB (not JSON) for better query performance on JSON fields
  • user_id is VARCHAR to support external auth systems (Firebase, Auth0, etc.)
  • Store image URLs (S3/Cloudflare R2), not local paths
  • All timestamps are UTC
  • Create indexes on user_id, created_at, and overall_status

JSON Field Structures

raw_ocr Structure

{ "front": [ { "text": "MRP: Rs. 150", "confidence": 0.95, "bbox": [[x1, y1], [x2, y2], [x3, y3], [x4, y4]] } ], "back": [...] }

extracted_fields Structure

{ "common_name": { "value": "Mixed Fruit Jam", "confidence": 0.92, "source": [[x1, y1], ...] }, "mrp": { "value": "Rs. 150", "confidence": 0.95, "source": [[x1, y1], ...] }, "net_quantity": {...}, "manufacturer_address": [...], ... }

[ { "rule_id": "LM6_1_b", "clause": "Rule 6(1)(b)", "field": "common_name", "description": "Common or generic name must be declared", "status": "passed", "evidence": {...} }, ... ]

API Endpoints

FastAPI backend running on http://localhost:8000

Core Endpoints (No Database)

POST /ocr

Description: Raw OCR text extraction only

Input: FormData with front and back image files

Output: Raw OCR blocks with text, confidence, and bounding boxes

// Example Response { "front": [{"text": "...", "confidence": 0.95, "bbox": [...]}], "back": [...] }

POST /evaluate

Description: OCR + compliance check (no database save)

Input: FormData with front and back image files

Output: Extracted fields, rule results, and summary

// Example Response { "fields": { "common_name": {"value": "...", "confidence": 0.92, ...}, "mrp": {...}, ... }, "rules": [ {"rule_id": "LM6_1_b", "status": "passed", ...}, ... ], "summary": { "passed": 6, "needs_review": 1, "failed": 1 } }

Database-Backed Endpoints

POST /scans

Description: Run OCR + compliance and save to database

Input: FormData with front, back, and optional user_id query param

Output: Same as /evaluate plus scan_id and created_at

curl -X POST "http://localhost:8000/scans?user_id=user123" \ -F "front=@front.jpg" \ -F "back=@back.jpg"

GET /scans

Description: List scan history for a user

Query Params:

  • user_id (required): User identifier
  • limit (optional, default 20): Max results
  • offset (optional, default 0): Pagination offset
curl "http://localhost:8000/scans?user_id=user123&limit=20&offset=0" // Response { "total": 50, "scans": [ { "scan_id": "uuid", "front_image_url": "front.jpg", "passed": 6, "needs_review": 1, "failed": 1, "overall_status": "non_compliant", "created_at": "2026-09-05T05:50:00" }, ... ] }

GET /scans/{scan_id}

Description: Get full details of a single scan

Output: Complete scan data including raw_ocr and rules_result

DELETE /scans/{scan_id}

Description: Delete a scan by ID

Output: Confirmation message

GET /scans/stats/summary

Description: Aggregate compliance statistics

Query Params: user_id

// Response { "total_scans": 50, "compliant": 35, "non_compliant": 15, "compliance_rate": 70.0 }
